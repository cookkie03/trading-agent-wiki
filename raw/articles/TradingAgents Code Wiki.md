The [`TradingAgents`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L28) framework automates financial market analysis, strategy formulation, and risk management. It models a collaborative trading firm environment by employing specialized AI agents to generate actionable insights.

The system uses a graph-based architecture to manage complex multi-agent workflows. This architecture orchestrates dynamic agent integration, conditional logic, and state propagation. For more details on its structure and flow, see [System Overview and Interaction](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction).

Specialized agents perform distinct roles in the trading process. These roles include financial analysts, investment researchers, risk management debaters, and decision-making managers. A dedicated trader agent translates final decisions into transaction proposals. The specific functions of each agent are described in [Agent Definitions and Roles](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles).

Financial market data from various vendors and social media platforms feeds the system's analysis. A unified interface provides agents with access to stock prices, technical indicators, fundamental reports, news, and sentiment data, while preventing look-ahead bias. Large Language Models drive agent intelligence through an abstracted client interface that manages model interactions and capabilities. For information on data acquisition, consult [Financial Data Ingestion and Processing](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-data-ingestion-and-processing). Further details on LLM integration are available in [Large Language Model (LLM) Integration](https://codewiki.google/github.com/tauricresearch/tradingagents#large-language-model-llm-integration).

Users interact with the framework through a command-line interface or a Python API. The [`TradingAgents`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L28) framework is a multi-agent system for financial trading that employs Large Language Models (LLMs) to automate market analysis, strategy formulation, and risk management. It models the collaborative environment of a trading firm, where specialized agents work together to navigate financial markets. The system offers interaction through a command-line interface (CLI) and a Python API, integrating various financial data sources and featuring robust persistence mechanisms.

At its core, the system utilizes a graph-based architecture, orchestrated by [`LangGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L32), to manage complex multi-agent workflows. This architecture facilitates dynamic agent integration, conditional logic, and state propagation, enabling agents to operate in sequence or in parallel based on real-time market conditions and internal debates. Further details on this orchestration can be found in [Orchestration and Graph-Based Workflows](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-orchestration-and-graph-based-workflows).

User interaction with the [`TradingAgents`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L28) framework can occur through two primary avenues:

- **Command-Line Interface (CLI)**: The CLI, primarily managed by files within the [`cli`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/cli) directory, provides an interactive way to configure and run trading analyses. Users can specify parameters such as ticker symbols, analysis dates, LLM providers, and the depth of research. The CLI displays real-time progress updates, including agent statuses, LLM calls, and tool usage, using an interactive terminal interface. Upon completion, it can generate and save comprehensive reports. More information is available in [Command-Line Interface (CLI) for User Interaction](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-command-line-interface-cli-for-user-interaction).
- **Python API**: For programmatic access, the [`TradingAgentsGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L50) class, located in [`tradingagents/graph/trading_graph.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py), serves as the main entry point. Developers can instantiate this class with a configuration object and invoke its [`propagate`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L295) method to initiate the multi-agent process for a given financial instrument and date. This allows for integration into larger applications or automated scripts. Refer to [Python API for Programmatic Access](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-python-api-for-programmatic-access) for more details.

The system incorporates several persistence and recovery mechanisms to ensure data integrity and workflow continuity. LangGraph's checkpointing functionality, managed by [`get_checkpointer`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L34) and [`checkpoint_step`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L51) in [`tradingagents/graph/checkpointer.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py), enables the system to save its state after each node execution. This allows for the resumption of interrupted runs from the last successful step. Additionally, a persistent decision log, [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) in [`tradingagents/agents/utils/memory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py), records past trading decisions and their outcomes, facilitating a reflection process for continuous learning and improvement. This aspect is further elaborated in [Persistence, Checkpointing, and Reflection](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-persistence-checkpointing-and-reflection).

Financial data is a crucial input for the trading agents. The system retrieves diverse data types, including stock prices, technical indicators, fundamental reports, news, and social media sentiment, from various vendors such as Alpha Vantage and yfinance, as well as platforms like Reddit and StockTwits. This data is made available to the agents through a unified and abstracted interface. The handling of these data sources is detailed in the [Financial Data Ingestion and Processing](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-data-ingestion-and-processing) section.

Configuration management is flexible, with default settings centralized in [`tradingagents/default_config.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/default_config.py). These settings can be overridden via environment variables, ensuring adaptability across different deployment environments and user preferences.

The multi-agent financial trading system orchestrates complex workflows for financial analysis, investment decision-making, and risk management using a graph-based architecture built upon LangGraph. This architecture dynamically constructs, manages, and executes workflows, incorporating conditional logic, state propagation, and dynamic agent integration to simulate sophisticated trading processes.

At the core of this orchestration is the [`TradingAgentsGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L50) class, defined in [`tradingagents/graph/trading_graph.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py). This class acts as the central orchestrator, initializing various components including Large Language Model (LLM) clients, a persistent [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10), and specialized [`ToolNode`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L5) instances for data fetching. It integrates several logical components— [`ConditionalLogic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/conditional_logic.py#L6), [`GraphSetup`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L14), [`Propagator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py#L11), [`Reflector`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py#L6), and [`SignalProcessor`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/signal_processing.py#L20) —to manage the entire lifecycle of a trading decision for a given asset.

The workflow begins with the construction of the agent graph, handled by the [`GraphSetup`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L14) class in [`tradingagents/graph/setup.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py). This component dynamically builds a [`StateGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L4) using an [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) to represent the current context. It incorporates nodes for different types of agents—analysts, researchers, and managers—and defines the conditional edges that govern the flow of information and control. The [`setup_graph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L32) method allows for flexible configurations by accepting a list of selected analysts, thereby tailoring the initial analytical workflow.

Conditional logic within the graph is managed by the [`ConditionalLogic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/conditional_logic.py#L6) class in [`tradingagents/graph/conditional_logic.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/conditional_logic.py). This class centralizes decision-making for various analytical and debate processes. It inspects the [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) to determine the next step in a workflow. For instance, it decides whether a specific analytical phase (e.g., market, news, fundamentals) should continue based on the presence of tool calls, or if an investment debate or risk analysis debate should progress to the next participant based on turn counts and speaker history. This enables the graph to dynamically adapt its path based on the ongoing state.

State propagation is managed by the [`Propagator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py#L11) class in [`tradingagents/graph/propagation.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py). This component initializes the [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) at the beginning of a graph run, populating it with essential information such as the company of interest, trade date, asset type, and any relevant past context from the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10). It also prepares arguments for invoking the graph, such as recursion limits. The [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) itself, defined using [`TypedDict`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L2) schemas in [`tradingagents/agents/utils/agent_states.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py), is crucial for maintaining and passing complex multi-agent state, including reports, debate histories, and decisions, between nodes in the graph. This state management ensures that each agent operates with the most up-to-date and comprehensive context.

The system supports robust persistence and recovery through checkpointing, which is managed in [`tradingagents/graph/checkpointer.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py). This mechanism uses per-ticker SQLite databases to store the state of the LangGraph, preventing contention and allowing for runs to be resumed from the last successful step in case of interruption. The [`get_checkpointer`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L34) function provides a context manager for [`SqliteSaver`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L14) instances, ensuring proper database handling. This checkpointing, along with the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) described in [Persistence, Checkpointing, and Reflection](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-persistence-checkpointing-and-reflection), contributes to the system's reliability.

Dynamic agent integration is achieved through factory functions, as seen in [`tradingagents/agents/__init__.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py), which create specific agent instances (analysts, researchers, managers, traders) based on the required role and configuration. These agents, detailed further in [Agent Definitions and Roles](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles), operate as nodes within the graph, interacting with each other by reading from and writing to the shared [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46). The [`TradingAgentsGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L50) and [`GraphSetup`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L14) classes are responsible for wiring these individual agent nodes and their associated tool nodes into a cohesive, executable workflow.

The system incorporates several mechanisms to ensure data persistence, enable recovery from interruptions, and facilitate continuous learning from past trading decisions.

One such mechanism is LangGraph checkpointing, which allows for the resumption of an interrupted multi-agent workflow from its last successful step. This is managed through per-ticker SQLite databases to prevent contention during concurrent operations. The [`get_checkpointer`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L34) function in [`tradingagents/graph/checkpointer.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py) provides a context manager for [`SqliteSaver`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L14) instances, which connect to a specific database identified by a unique [`thread_id`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L28) generated for each ticker and date. This approach enables the system to check for existing checkpoints using [`has_checkpoint`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L46) and [`checkpoint_step`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L51), and to clear them as needed via [`clear_checkpoint`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L76) or [`clear_all_checkpoints`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py#L65). The primary entry point for orchestrating these runs, [`propagate`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L295) in [`tradingagents/graph/trading_graph.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py), utilizes this checkpointing to ensure robustness.

Another key persistence component is the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) system, implemented in [`tradingagents/agents/utils/memory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py). This system maintains a persistent, append-only markdown log of trading decisions, outcomes, and reflections. It provides functionalities such as [`store_decision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L31) for adding new pending decisions and [`update_with_outcome`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L100) for atomically updating these entries with actual trade results (raw and alpha returns) and generated reflections. The [`get_past_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L71) method allows agents to retrieve formatted past analyses from this log, injecting valuable historical context into LLM prompts to inform future decisions. The log also includes mechanisms for rotation ([`_apply_rotation`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L221)) to manage its size by pruning older, resolved entries while preserving pending ones. This log serves as a foundational element for the system's ability to learn and adapt over time.

Integral to this continuous learning is the reflection process, facilitated by the [`Reflector`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py#L6) class in [`tradingagents/graph/reflection.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py). After a trading decision's outcome is known, this process leverages an LLM to generate concise, prose-based reflections. These reflections focus on the accuracy of the directional call, the validity of the investment thesis, and key lessons learned from the trade. The [`reflect_on_final_decision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py#L31) method generates these reflections, which are then stored in the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) alongside the trade outcomes. This deferred reflection ([`_resolve_pending_entries`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L255) in [`tradingagents/graph/trading_graph.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py)) ensures that the system can analyze its past performance and incorporate those insights into future decision-making cycles by providing relevant historical context through the [`get_past_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L71) function.

## Trading Agent Ecosystem and Orchestration

The [`tradingagents`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/pyproject.toml#L36) package orchestrates a multi-agent financial trading system, integrating Large Language Models (LLMs) for tasks ranging from financial analysis to investment decision-making and risk management. This system employs a modular, state-aware design, with a graph-based architecture that manages complex workflows and interactions between different agent types.

At its core, the system utilizes a [`langgraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L32) framework, with the [`TradingAgentsGraph`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py#L50) class in [`tradingagents/graph/trading_graph.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/trading_graph.py) serving as the central orchestrator for the entire trading decision lifecycle. This graph dynamically constructs and executes workflows, allowing for conditional logic, state propagation, and checkpointing for robust operation. The [`GraphSetup`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py#L14) class in [`tradingagents/graph/setup.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/setup.py) is responsible for building this graph, defining its nodes (agents) and edges (workflow transitions), while [`ConditionalLogic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/conditional_logic.py#L6) in [`tradingagents/graph/conditional_logic.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/conditional_logic.py) determines the flow's next steps based on the current [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46). This allows for dynamic decision paths, such as continuing a debate or transitioning to a different analytical phase. State propagation is managed by the [`Propagator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py#L11) in [`tradingagents/graph/propagation.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py), which initializes the [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) and configures graph invocation parameters.

Financial market data is retrieved and processed through a unified and abstracted interface, primarily managed within the [`tradingagents/dataflows`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows) directory. This subsystem handles interactions with various data vendors like Alpha Vantage and yfinance, as well as social media platforms, providing agents with access to stock prices, technical indicators, fundamental reports, news, and sentiment data. The system prevents look-ahead bias through careful date filtering of financial reports and news. More details on data ingestion can be found in [Financial Data Ingestion and Processing](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-data-ingestion-and-processing).

Agent intelligence is driven by a unified LLM client interface, detailed in [Large Language Model (LLM) Integration](https://codewiki.google/github.com/tauricresearch/tradingagents#large-language-model-llm-integration). This interface, defined in [`tradingagents/llm_clients`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients), abstracts away provider-specific complexities, offering consistent model creation, content normalization, and validation across various LLM providers (e.g., Anthropic, Google, OpenAI).

The ecosystem features a diverse set of agents, each with a specialized role, as described in [Agent Definitions and Roles](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles). These include:

- **Analysts** (e.g., [`fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L4), [`market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L5), [`news_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L6), [`sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L13) in [`tradingagents/agents/analysts`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts)) who generate reports by integrating LLMs with specialized data retrieval tools.
- **Research Debaters** (e.g., [`bull_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L5), [`bear_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L5) in [`tradingagents/agents/researchers`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers)) who engage in simulated investment debates to generate pro- or anti-investment arguments.
- **Risk Management Debaters** (e.g., [`aggressive_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L15), [`conservative_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L16), [`neutral_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L17) in [`tradingagents/agents/risk_mgmt`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt)) who evaluate investment plans from different risk perspectives.
- **Managers** (e.g., [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19), [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27) in [`tradingagents/agents/managers`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers)) who synthesize debate outcomes into structured investment plans and final trading decisions.

The system incorporates robust persistence mechanisms, including LangGraph checkpointing via [`tradingagents/graph/checkpointer.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/checkpointer.py) for recovery and the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) in [`tradingagents/agents/utils/memory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py) for maintaining a persistent record of trading decisions and reflections. This memory log, along with the [`Reflector`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py#L6) in [`tradingagents/graph/reflection.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py), supports a continuous learning process where past outcomes inform future decisions through automated reflection. The [`SignalProcessor`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/signal_processing.py#L20) in [`tradingagents/graph/signal_processing.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/signal_processing.py) extracts actionable portfolio ratings from agent outputs.

## Financial Data Ingestion and Processing

Financial data ingestion and processing within the trading system involves acquiring, abstracting, and managing financial market data from various third-party vendors. This includes stock prices, technical indicators, fundamental reports, news, and social media sentiment. The system ensures that agents have access to a unified and abstracted interface, regardless of the underlying data source.

The [`tradingagents/dataflows`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows) directory provides the core infrastructure for data acquisition. This layer handles interactions with providers such as Alpha Vantage and yfinance for traditional financial data, and Reddit and StockTwits for social media sentiment. It manages API interactions, including rate limiting and API key retrieval, to ensure reliable data flows. For instance, utilities within [`tradingagents/dataflows/alpha_vantage_common.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py) abstract common tasks like API key retrieval and request execution for Alpha Vantage, while [`yf_retry`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L16) in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py) provides robust retry mechanisms for yfinance API calls.

A key aspect of this system is the prevention of look-ahead bias, especially important for backtesting and simulation environments. Functions like [`_filter_reports_by_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py#L4) in [`tradingagents/dataflows/alpha_vantage_fundamentals.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py) and [`filter_financials_by_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L96) in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py) ensure that financial reports and market data are strictly filtered by a current date ([`curr_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L190)). This prevents the use of future information that would not be available in a real-time trading scenario.

The [`tradingagents/dataflows/interface.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/interface.py) module acts as a central hub for data retrieval, providing a unified interface across different vendors. It maps generic data requests to vendor-specific implementations and incorporates a fallback mechanism. This allows the system to attempt data retrieval from a primary vendor and, if specific errors like rate limits occur (e.g., [`AlphaVantageRateLimitError`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py#L38)), it can seamlessly switch to an alternative vendor to fulfill the request. This dynamic routing and fallback strategy enhances the system's resilience and ensures continuous data availability.

Beyond traditional financial metrics, the system also integrates social media sentiment data. Modules like [`tradingagents/dataflows/reddit.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/reddit.py) and [`tradingagents/dataflows/stocktwits.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stocktwits.py) fetch ticker-specific discussions and messages from platforms like Reddit and StockTwits, processing them into a format suitable for consumption by LLM agents. This enables agents to incorporate public sentiment into their analysis, which is crucial for modern market strategies.

### Unified Data Access and Vendor Abstraction

The system provides a unified interface for agents to access financial market data from various third-party vendors, abstracting away vendor-specific implementations and offering fallback mechanisms. This centralized access is managed through the module [`tradingagents/dataflows/interface.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/interface.py), which acts as the primary entry point for fetching data.

The core of this abstraction relies on a mapping of generic tool names (e.g., [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7), [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), [`get_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L6)) to their respective vendor-specific functions (e.g., [`get_alpha_vantage_stock`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/interface.py#L15) from [`tradingagents/dataflows/alpha_vantage_stock.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_stock.py) or [`get_YFin_data_online`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L9) from [`tradingagents/dataflows/y_finance.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py)). This allows different parts of the system to request data using a consistent API without needing to know the underlying data provider.

A routing mechanism within [`tradingagents/dataflows/interface.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/interface.py) determines the appropriate vendor to use for a given data request. This determination is based on the application's configuration, which can specify preferred vendors at both a general category level (e.g., for all "core stock APIs") and a more granular tool-specific level.

To enhance reliability, the system incorporates a vendor fallback strategy. If a primary vendor fails, particularly due to rate limiting (e.g., an [`AlphaVantageRateLimitError`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py#L38) from [`tradingagents/dataflows/alpha_vantage_common.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py)), the system automatically attempts to retrieve the data from an alternative configured vendor. This ensures that data retrieval remains robust even if one provider experiences temporary issues.

For further details on how various financial data types are ingested and processed, refer to [Financial Data Ingestion and Processing](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-data-ingestion-and-processing).

### Financial Data Retrieval from Alpha Vantage

The system integrates with the Alpha Vantage API to retrieve various types of financial data, including stock prices, technical indicators, fundamental reports, and news. A core set of utilities, found in [`tradingagents/dataflows/alpha_vantage_common.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py), manages the API interactions. These utilities handle API key retrieval, standardize date formats for requests, execute HTTP requests, and manage rate limits to ensure consistent and reliable data fetching. Error handling, specifically for rate limiting, is managed through a custom exception, [`AlphaVantageRateLimitError`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_common.py#L38).

For stock price information, the system uses functionalities defined in [`tradingagents/dataflows/alpha_vantage_stock.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_stock.py) to fetch daily adjusted OHLCV (Open, High, Low, Close, Volume) data. This module determines the appropriate data retrieval scope ([`compact`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/reflection.py#L17) for recent data or [`full`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L31) for historical data) based on the requested date range.

Technical indicators are retrieved and processed via logic in [`tradingagents/dataflows/alpha_vantage_indicator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_indicator.py). This component supports various indicators like SMA, MACD, and RSI, providing not only the data but also descriptions and usage tips. It dynamically constructs API calls based on the requested indicator and handles specific cases, such as the absence of direct API support for VWMA.

Fundamental financial data, such as company overviews, balance sheets, cash flow statements, and income statements, is handled by [`tradingagents/dataflows/alpha_vantage_fundamentals.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py). A key feature of this module is its mechanism to prevent look-ahead bias by filtering financial reports to exclude any data published after a specified current date. This ensures that simulations and analyses only use information that would have been historically available.

News and sentiment data, along with insider transaction information, are retrieved using functions in [`tradingagents/dataflows/alpha_vantage_news.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_news.py). This includes fetching company-specific news and global market news, with options to filter by date range and topics.

All these specialized data retrieval functionalities are aggregated and exposed through [`tradingagents/dataflows/alpha_vantage.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage.py), which acts as a unified interface for accessing Alpha Vantage data within the application. This modular design separates concerns, making the API cleaner and easier to navigate for developers.

### Financial Data Retrieval from yfinance

The system integrates with the [`yfinance`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L194) library to acquire various financial market data, including historical OHLCV (Open, High, Low, Close, Volume) data, technical indicators, fundamental financial statements, and news articles. Data retrieval functions within [`tradingagents/dataflows/y_finance.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py) are designed to provide consistent CSV-formatted outputs, which are suitable for consumption by other parts of the system.

Historical OHLCV data for specific symbols over defined periods is retrieved, with measures taken to round numerical data and clean timezone information. Technical indicators such as Moving Averages, MACD, RSI, and Bollinger Bands are calculated based on this OHLCV data. An optimized bulk calculation approach is used for efficiency, with a fallback to per-day calculations if necessary. For fundamental analysis, functions retrieve key financial metrics, balance sheets, cash flow statements, and income statements, available in both annual and quarterly frequencies. Insider transaction data is also accessible through this integration.

A key aspect of the data ingestion process is the prevention of look-ahead bias, which is crucial for accurate backtesting and analysis. This is achieved by ensuring that all retrieved data, including financial statements, is strictly filtered to only include information available up to a specified [`curr_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L190). This mechanism is implemented in utilities like [`filter_financials_by_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L96) within [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py).

News retrieval capabilities distinguish between stock-specific articles and broader global macroeconomic news. Functions in [`tradingagents/dataflows/yfinance_news.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/yfinance_news.py) fetch news, extract relevant details (title, summary, publisher, link, publication date), and apply date-based filtering to prevent future-dated articles from being included. A deduplication mechanism is also in place for global news to avoid redundant entries from multiple search queries.

To enhance reliability, API calls to [`yfinance`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L194) are wrapped with a retry mechanism, [`yf_retry`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L16), defined in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py). This mechanism incorporates exponential backoff to handle transient issues like rate limiting, ensuring more robust data fetching operations. The system also employs caching for OHLCV data to speed up subsequent requests for the same symbols. Further details on data ingestion and processing can be found in [Financial Data Ingestion and Processing](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-data-ingestion-and-processing).

The system acquires social media sentiment data from platforms like Reddit and StockTwits to inform trading decisions. This process involves fetching ticker-specific discussions and messages directly from public APIs and formatting them into a consistent structure for downstream analysis.

For Reddit, the system uses the [`fetch_reddit_posts`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/reddit.py#L59) function in [`tradingagents/dataflows/reddit.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/reddit.py) to retrieve posts related to a given stock ticker from specified subreddits. It interacts directly with Reddit's public JSON endpoints, handling rate limits and gracefully managing network or parsing errors by returning placeholder strings if data is unavailable. The extracted data, including post titles, scores, comments, and text content, is then formatted into plaintext blocks suitable for prompt injection into language models.

Similarly, for StockTwits, the [`fetch_stocktwits_messages`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stocktwits.py#L30) function in [`tradingagents/dataflows/stocktwits.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stocktwits.py) retrieves recent messages for a specified stock ticker. This function performs an HTTP GET request to the public StockTwits API, with robust error handling for network issues and JSON parsing. It extracts message timestamps, usernames, sentiment (Bullish, Bearish, or unlabeled), and message bodies. A summary of bullish and bearish sentiment counts is generated, followed by a list of formatted messages, providing a clear overview of social media sentiment for a given asset. Both implementations are designed to ensure uniform output formats, minimizing complexity for consuming components of the system. For additional details on how this sentiment data is then used by specific agents, refer to [Sentiment Analyst Agent](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-analysis-agents-sentiment-analyst-agent).

### Look-Ahead Bias Prevention and Data Processing

Preventing look-ahead bias is fundamental for valid financial simulations and backtesting, as it ensures that historical analyses only use data that would have been genuinely available at the time of a simulated decision. The system implements several strategies to achieve this, particularly for financial statements, stock market data, and news.

For financial statements and fundamental reports, functions such as [`_filter_reports_by_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py#L4) in [`tradingagents/dataflows/alpha_vantage_fundamentals.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py) are used to filter out reports whose [`fiscalDateEnding`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/alpha_vantage_fundamentals.py#L16) is later than the current simulation date ([`curr_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L190)). This ensures that financial data is processed as it would have been publicly disclosed, avoiding the use of future information. Similarly, the [`filter_financials_by_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L96) function in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py) handles filtering columns in financial statement data (which represent fiscal period end dates in [`yfinance`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L194) data) to only include those that are less than or equal to [`curr_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L190).

When retrieving historical stock OHLCV data and technical indicators, the [`load_ohlcv`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L48) function in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py) applies a critical filter: data is limited to rows where the "Date" is less than or equal to [`curr_date_dt`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L138). This ensures that any calculated indicators or stock prices reflect only information available up to the point of a simulated decision.

News data also incorporates look-ahead bias prevention. The [`get_global_news_yfinance`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/yfinance_news.py#L111) function in [`tradingagents/dataflows/yfinance_news.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/yfinance_news.py) includes a check to filter out news articles published after the [`curr_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L190), preventing any future-dated information from influencing current decisions.

Beyond bias prevention, the system includes general data cleaning and normalization practices. The [`_clean_dataframe`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py#L35) function in [`tradingagents/dataflows/stockstats_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stockstats_utils.py) processes raw stock data by parsing dates, handling missing values, and filling price gaps to ensure data quality and consistency for subsequent analysis.

## Large Language Model (LLM) Integration

The system integrates Large Language Models (LLMs) through a unified client interface, abstracting interactions with various providers such as OpenAI, Anthropic, Google, and Azure. This abstraction facilitates consistent model creation, content normalization, and management of model-specific capabilities, while also centralizing API key handling and enabling lazy loading of provider-specific SDKs.

The core of this integration is the [`BaseLLMClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L25) abstract interface, defined in [`tradingagents/llm_clients/base_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py), which establishes a consistent API for all LLM client implementations. The [`create_llm_client`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/factory.py#L15) factory function, found in [`tradingagents/llm_clients/factory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/factory.py), dynamically instantiates specific LLM clients, such as [`AnthropicClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py#L43) or [`OpenAIClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L180), based on the requested provider and model. This dynamic instantiation includes lazy loading of provider-specific SDKs, which prevents unnecessary overhead until a particular client is needed.

A critical aspect of the LLM integration is content normalization. The [`normalize_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L6) function, also in [`tradingagents/llm_clients/base_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py), standardizes LLM responses, converting potentially structured or block-based output into a plain string. This ensures uniformity across different LLM providers, simplifying downstream processing by agents. Wrappers like [`NormalizedChatAnthropic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py#L31) in [`tradingagents/llm_clients/anthropic_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py) ensure this normalization is applied during [`invoke`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/azure_client.py#L18) calls.

The system also addresses model-specific behaviors and capabilities. [`ModelCapabilities`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L31), defined in [`tradingagents/llm_clients/capabilities.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py), manages unique attributes for each model, such as support for [`tool_choice`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L59) or JSON mode. This prevents hardcoding model-specific logic within client implementations and allows for dynamic adaptation to various LLM APIs. For instance, specific client implementations may handle provider-specific parameter mapping or echo [`reasoning_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L38) for models like DeepSeek, as detailed in [`tradingagents/llm_clients/openai_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py).

A centralized [`MODEL_OPTIONS`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/model_catalog.py#L76) catalog, maintained in [`tradingagents/llm_clients/model_catalog.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/model_catalog.py), categorizes known models by provider and usage mode ("quick" or "deep"). This catalog supports model validation, ensuring that only supported models are utilized. The [`validate_model`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/validators.py#L13) function in [`tradingagents/llm_clients/validators.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/validators.py) performs this validation, with special considerations for providers like Ollama or OpenRouter, which accept any model.

This standardizes the retrieval of API keys and environment variables for various LLM providers, including specific handling for Azure OpenAI as discussed in [`tradingagents/llm_clients/azure_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/azure_client.py). This ensures secure and consistent access to LLM services across the system. Consistency improvements and outstanding issues related to this integration are documented in [`tradingagents/llm_clients/TODO.md`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/TODO.md).

### LLM Client Interface and Dynamic Instantiation

The system integrates various Large Language Models (LLMs) through a unified, consistent interface, abstracting away provider-specific complexities. This is achieved through a common base interface and a factory mechanism for dynamic client instantiation.

The [`BaseLLMClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L25) in [`tradingagents/llm_clients/base_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py) defines an abstract interface that all concrete LLM client implementations must adhere to. This interface establishes a consistent contract for interacting with different LLM services, regardless of their underlying APIs. It includes abstract methods for retrieving the LLM instance ([`get_llm`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L55)) and validating the model ([`validate_model`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/validators.py#L13)), ensuring that each client provides these core functionalities.

The [`create_llm_client`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/factory.py#L15) factory function, located in [`tradingagents/llm_clients/factory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/factory.py), is the primary entry point for instantiating LLM clients. This function dynamically creates specific client implementations (e.g., for OpenAI, Anthropic, Google, or Azure) based on the requested provider and model. A key design choice is the use of lazy loading, where provider-specific SDKs are only imported when a client for that provider is explicitly requested. This approach optimizes startup performance by avoiding unnecessary loading of potentially heavy dependencies and prevents configuration errors for unused providers. The factory function categorizes providers, for instance, by grouping those compatible with the OpenAI chat completions API, which are then handled by a single [`OpenAIClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L180) implementation.

This centralized approach to client creation and interface definition allows the trading agents to interact with different LLM providers through a standardized API, promoting modularity and simplifying future integrations of new LLM services. Further details on content normalization and response handling are available in [Content Normalization and Response Handling](https://codewiki.google/github.com/tauricresearch/tradingagents#large-language-model-llm-integration-content-normalization-and-response-handling).

### Content Normalization and Response Handling

The system standardizes Large Language Model (LLM) responses into plain strings through the [`normalize_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L6) function, which is defined in [`tradingagents/llm_clients/base_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py). This is crucial because many LLM APIs return content in structured formats (e.g., lists of blocks with different types like 'reasoning' or 'text'). By extracting and joining only the 'text' blocks, [`normalize_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L6) ensures that downstream processes and agents consistently receive a simple string, simplifying parsing and reducing complexity.

To achieve this consistency across different LLM providers, specific wrappers are used. For instance, [`NormalizedChatAnthropic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py#L31) in [`tradingagents/llm_clients/anthropic_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py), [`NormalizedAzureChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/azure_client.py#L15) in [`tradingagents/llm_clients/azure_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/azure_client.py), [`NormalizedChatGoogleGenerativeAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/google_client.py#L9) in [`tradingagents/llm_clients/google_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/google_client.py), and [`NormalizedChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L13) in [`tradingagents/llm_clients/openai_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py) all extend their respective [`langchain`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/cli/main.py#L945) components. These wrappers override the [`invoke`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/azure_client.py#L18) method to apply [`normalize_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/base_client.py#L6) to the LLM's output before returning it, ensuring that regardless of the LLM provider, the content is consistently formatted. This approach helps maintain a uniform interface for LLM interactions throughout the system. For more details on the general LLM integration framework, refer to [LLM Client Interface and Dynamic Instantiation](https://codewiki.google/github.com/tauricresearch/tradingagents#large-language-model-llm-integration-llm-client-interface-and-dynamic-instantiation).

### Model-Specific Capabilities and Behavioral Adjustments

The system manages the diverse behaviors and requirements of different Large Language Models (LLMs) through a declarative approach, primarily using the [`ModelCapabilities`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L31) dataclass defined in [`tradingagents/llm_clients/capabilities.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py). This mechanism centralizes knowledge about per-model quirks, such as whether an LLM supports [`tool_choice`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L59), [`json_mode`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L24), or [`json_schema`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L91), and what its preferred method for structured output is. This prevents conditional logic from being hardcoded directly into the client implementations, making the system more adaptable to new models or API changes.

The [`get_capabilities`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L120) function in [`tradingagents/llm_clients/capabilities.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py) is the main interface for querying these capabilities. It first attempts an exact match for a model ID, then falls back to regular expression pattern matching for broader compatibility, and finally defaults to a general set of capabilities if no specific match is found. This layered lookup ensures that both well-known models and future variants are handled appropriately.

Client implementations within the [`tradingagents/llm_clients`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients) directory, such as [`OpenAIClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L180), [`AnthropicClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/anthropic_client.py#L43), and [`GoogleClient`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/google_client.py#L20), leverage these capabilities to adjust their behavior dynamically. For instance, [`tradingagents/llm_clients/openai_client.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py) includes specialized subclasses like [`DeepSeekChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L68) and [`MinimaxChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L112) to handle provider-specific nuances. [`DeepSeekChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L68) manages the [`reasoning_content`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L38) round-trip required by DeepSeek's thinking-mode models, ensuring that prior assistant turns' reasoning is echoed back to avoid errors. Similarly, [`MinimaxChatOpenAI`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L112) addresses MiniMax's [`reasoning_split`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L41) parameter, which dictates how thinking blocks are placed in reasoning details for specific reasoning models. These client-side adjustments, guided by the [`ModelCapabilities`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/capabilities.py#L31), ensure correct interaction with LLMs that have non-standard API behaviors. For more details on the LLM client interface and its dynamic instantiation, see [LLM Client Interface and Dynamic Instantiation](https://codewiki.google/github.com/tauricresearch/tradingagents#large-language-model-llm-integration-llm-client-interface-and-dynamic-instantiation).

## Agent Definitions and Roles

The multi-agent financial trading system organizes its intelligence into distinct agent types, each with a specialized role in financial analysis, investment decision-making, and risk management. These agents are designed to be modular and state-aware, interacting within a graph-based workflow to achieve comprehensive trading strategies. The system provides factory functions for creating various agents, ensuring a consistent interface for their instantiation.

The primary agent types include:

- **Analysts**: These agents are responsible for gathering and synthesizing specific types of financial data.
	- **Fundamentals Analyst**: Focuses on a company's financial health by examining reports like balance sheets, income statements, and cash flows.
		- **Market Analyst**: Analyzes price action and technical indicators to identify trends and patterns.
		- **News Analyst**: Processes and summarizes relevant news, covering both company-specific and macroeconomic events.
		- **Sentiment Analyst**: Gauges market sentiment by analyzing data from social media platforms and news, providing a qualitative view of market perception.
- **Researchers**: These agents engage in simulated debates to explore investment theses from different perspectives.
	- **Bull Researcher**: Develops arguments in favor of an investment, highlighting growth potential and positive indicators.
		- **Bear Researcher**: Constructs counter-arguments, focusing on risks, competitive weaknesses, and negative factors.
- **Risk Management Debaters**: A specialized set of agents that scrutinize investment plans from various risk appetites.
	- **Aggressive Risk Debater**: Advocates for strategies with higher potential returns, often involving higher risk.
		- **Conservative Risk Debater**: Prioritizes capital preservation and risk mitigation, pushing for safer investment approaches.
		- **Neutral Risk Debater**: Provides a balanced perspective, critiquing both aggressive and conservative viewpoints to ensure a thorough risk assessment.
- **Managers**: These agents are responsible for synthesizing information from debates and analyses into actionable plans and decisions.
	- **Research Manager**: Consolidates the arguments from the investment debate into a structured [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61), which outlines the investment thesis and strategic actions.
		- **Portfolio Manager**: Integrates the [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) with the outcomes of the risk management debate to formulate a final [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171), which includes a rating and an executive summary of the trading strategy.
- **Trader**: This agent translates the [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) into a concrete [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109), detailing the specific actions to be taken, such as buy, sell, or hold, along with parameters like entry price and position sizing.

The public API for these agents is defined in [`tradingagents/agents/__init__.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py), which exposes factory functions (e.g., [`create_fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L14), [`create_bull_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L4), [`create_portfolio_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L24)) for their instantiation. This factory pattern centralizes the creation logic and simplifies agent integration.

The interactions between these agents are governed by a shared state, which is structured using [`TypedDict`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L2) schemas defined in [`tradingagents/agents/utils/agent_states.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py). These schemas, such as [`InvestDebateState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L7) and [`RiskDebateState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L21), track conversation histories, reports, and decisions, providing a consistent context for agents throughout their workflow. Additionally, [`Pydantic`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L90) schemas like [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61), [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109), and [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) in [`tradingagents/agents/schemas.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py) enforce consistent structured output from the agents' LLMs, using field descriptions to guide the LLMs in generating precise and parsable results. This structured output is crucial for ensuring that the information exchanged between agents and ultimately presented to the user is clear and consistent. For more details on this, refer to [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms).

Agents also leverage a suite of specialized tools for data retrieval, such as [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7), [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), and [`get_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L6), which abstract the complexities of interacting with various financial data vendors. These tools are often dynamically bound to LLMs, allowing agents to fetch relevant information as needed during their analytical processes.

Furthermore, a persistent [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) system, detailed in [Persistence, Checkpointing, and Reflection](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-persistence-checkpointing-and-reflection), is used to record trading decisions and reflections, allowing agents to learn from past outcomes and refine future strategies.

### Agent State Management and Schemas

Agent states are managed through [`TypedDict`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L2) schemas to handle the complexity of multi-agent interactions. These schemas, defined in [`tradingagents/agents/utils/agent_states.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py), track conversation histories, reports, and decisions across various stages of the trading process. For example, [`InvestDebateState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L7) captures the progression of research team discussions, while [`RiskDebateState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L21) manages the arguments and responses within risk management debates. The central [`AgentState`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L46) aggregates this information, including key parameters such as the company of interest, asset type, and trade date, along with outputs from different analytical stages like market, sentiment, news, and fundamental reports.

Consistent structured output for LLM-generated reports, plans, and decisions is enforced through Pydantic schemas. The file [`tradingagents/agents/schemas.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py) defines these schemas, such as [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) for investment strategies, [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) for transaction recommendations, and [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) for final trade decisions. These schemas incorporate Enum types, like [`PortfolioRating`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L32) and [`TraderAction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L42), to ensure categorical fields have consistent, predefined values. The descriptions within these Pydantic [`Field`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L24) objects serve as instructions for the LLMs during content generation. To maintain compatibility with downstream systems, dedicated utility functions render these structured Pydantic instances into standardized Markdown formats for display and further processing.

The system employs mechanisms to bind LLMs to these schemas, ensuring structured output where possible. In situations where an LLM may not support structured output or fails to produce it, a robust fallback mechanism invokes the LLM to generate free-text content instead. This approach, detailed in [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms), prevents pipeline interruptions and logs the fallback event for diagnostic purposes. This ensures that agents consistently provide output in either a structured or readable free-text format. Additionally, a persistent [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) system, explained further in [Trading Memory Log and Context Management](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-trading-memory-log-and-context-management), records trading decisions and reflections, providing past context for LLM prompts and supporting continuous learning.

### Data Retrieval Tools and Utilities

Specialized LangChain tools facilitate the retrieval of financial data, abstracting interaction with various vendors. These tools, along with general utilities for language instruction and instrument context building, are centralized within the [`tradingagents/agents/utils`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils) directory. This design ensures that agents can access necessary data and context without needing to manage vendor-specific APIs directly.

The [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) function within [`tradingagents/agents/utils/agent_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py) generates consistent language instructions for agents, allowing for localization of their outputs. Similarly, [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39) constructs descriptive strings for financial instruments, helping agents correctly interpret and analyze asset-specific information, particularly for different asset types like cryptocurrencies.

Several LangChain tools are provided for fetching specific types of financial data:

- **Stock Data**: [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7) in [`tradingagents/agents/utils/core_stock_tools.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py) retrieves historical OHLCV (Open, High, Low, Close, Volume) data for a given ticker symbol and date range.
- **Technical Indicators**: The [`get_indicators`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/technical_indicators_tools.py#L6) tool in [`tradingagents/agents/utils/technical_indicators_tools.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/technical_indicators_tools.py) fetches one or more technical indicators for a stock, supporting various indicators like RSI or MACD.
- **Fundamental Data**: Tools like [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), [`get_balance_sheet`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L305), [`get_cashflow`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L337), and [`get_income_statement`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L369) in [`tradingagents/agents/utils/fundamental_data_tools.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/fundamental_data_tools.py) retrieve comprehensive fundamental financial statements and reports.
- **News and Insider Transactions**: [`get_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L6), [`get_global_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L24), and [`get_insider_transactions`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L401) from [`tradingagents/agents/utils/news_data_tools.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py) enable agents to gather company-specific news, broader market news, and details on insider trading activity.

All these data retrieval tools utilize a [`route_to_vendor`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/interface.py#L134) mechanism, which intelligently directs data requests to the appropriate backend vendor. This abstraction allows for flexibility in data sources and simplifies agent development by centralizing vendor management and potential fallbacks. The definition of these tools, their associated data schemas, and the overall framework for agent interaction are further detailed in [Agent Definitions and Roles](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles).

### Structured Output with LLMs and Fallback Mechanisms

The system employs a robust pattern to ensure that Large Language Models (LLMs) consistently produce structured output, while also providing a graceful fallback mechanism to free-text generation. This design prevents pipeline blockages and standardizes the logging of fallback events.

The [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) function, defined in [`tradingagents/agents/utils/structured.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py), attempts to configure an LLM to generate output conforming to a specified Pydantic schema. This is achieved by leveraging [`llm.with_structured_output(schema)`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L89), which is supported by various LLM providers. If an LLM does not support structured output, or if an error occurs during binding, the function logs a warning and returns [`None`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/cli/main.py#L64), indicating that structured output is not available for that particular LLM instance.

The [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) function, also found in [`tradingagents/agents/utils/structured.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py), handles the actual invocation of the LLM. It prioritizes the [`structured_llm`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L21) (if available from [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31)) to attempt a structured response based on the provided prompt. If this structured invocation is successful, the output is processed by a rendering function, which typically converts the structured data into a standardized Markdown string. However, if the structured invocation fails due to any reason (e.g., malformed JSON, transient provider issues), the system catches the exception, logs a warning, and gracefully falls back to invoking the original [`plain_llm`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L50) (the LLM without structured output wrapping) to generate a free-text response. This ensures that the system can always progress, even if structured output is temporarily unavailable or if a specific LLM lacks the capability.

This structured output and fallback mechanism is critical for agents such as the [Research Manager: Synthesizing Investment Plans](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-research-manager-synthesizing-investment-plans) and [Portfolio Manager: Deriving Final Trade Decisions](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-portfolio-manager-deriving-final-trade-decisions), which rely on specific schemas like [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) and [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) (defined in [`tradingagents/agents/schemas.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py)) for their operations. Similarly, the [Trader Agent Core Logic and LLM Interaction](https://codewiki.google/github.com/tauricresearch/tradingagents#trading-execution-agents-trader-agent-core-logic-and-llm-interaction) utilizes this mechanism to generate [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) objects.

### Trading Memory Log and Context Management

The [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) system provides a persistent, append-only log for trading decisions, reflections, and outcomes, playing a role in the system's [Persistence, Checkpointing, and Reflection](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-persistence-checkpointing-and-reflection) capabilities. This log, managed by the [`TradingMemoryLog`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L10) class in [`tradingagents/agents/utils/memory.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py), stores entries in a Markdown format, making them both human-readable and accessible for automated processing.

New trading decisions are initially stored as "pending" entries using [`store_decision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L31), which includes details such as ticker, trade date, the final trade decision, and a rating derived from [`parse_rating`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/rating.py#L30). To prevent redundant logging, an idempotency guard is in place to avoid duplicate pending entries.

Once the outcome of a trade is known, the [`update_with_outcome`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L100) function atomically updates the corresponding pending entry. This involves replacing the "pending" status with actual return figures (raw return, alpha return, holding days) and appending a [`REFLECTION`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L17) section, allowing the system to learn from past performance. For efficiency, multiple updates can be processed using [`batch_update_with_outcomes`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L165), which handles several entries in a single atomic write operation.

The log also supports generating historical context for large language model (LLM) prompts through [`get_past_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L71). This function compiles formatted summaries of past trading analyses, distinguishing between analyses of the same ticker ([`n_same`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L71)) and cross-ticker lessons ([`n_cross`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L71)). This historical context helps inform subsequent agent decisions by providing relevant past performance and reflections.

Log rotation is managed by [`_apply_rotation`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L221), which drops the oldest resolved entries when the log size exceeds a configured maximum, while always preserving pending decisions. This ensures the log remains manageable without losing critical ongoing information. The system leverages regular expressions ([`_DECISION_RE`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L16), [`_REFLECTION_RE`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/memory.py#L17)) for efficient parsing of decision and reflection content from log entries.

## Financial Analysis Agents

The financial analysis agents within the system produce detailed reports covering fundamentals, market trends, news, and sentiment for a given company or asset. These agents leverage large language models (LLMs) and integrate with specialized tools or pre-fetched data to generate their insights, acting as modular components within a broader multi-agent workflow.

A [`fundamentals_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L15) is initialized by [`create_fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L14) in [`tradingagents/agents/analysts/fundamentals_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py). This agent generates a comprehensive fundamental analysis report. It uses tools such as [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), [`get_balance_sheet`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L305), [`get_cashflow`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L337), and [`get_income_statement`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L369) to retrieve financial data. An LLM, guided by a detailed system message, processes this data to produce insights and a structured Markdown table.

For market analysis, [`create_market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py#L11) in [`tradingagents/agents/analysts/market_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py) sets up an agent that analyzes financial markets. This agent selects and applies various technical indicators, such as Moving Averages, MACD, and RSI, by first retrieving stock data using [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7) and then calculating indicators via [`get_indicators`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/technical_indicators_tools.py#L6). The LLM is extensively prompted to generate detailed reports with actionable insights and a Markdown table summary based on this analysis.

News analysis is handled by the agent created by [`create_news_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L11) in [`tradingagents/agents/analysts/news_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py). This agent specializes in generating reports on trading and macroeconomic news. It uses news retrieval tools, including [`get_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L6) for company-specific information and [`get_global_news`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/news_data_tools.py#L24) for broader market perspectives, allowing the LLM to synthesize structured reports with actionable insights and a Markdown table.

The [`create_sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L38) function in [`tradingagents/agents/analysts/sentiment_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py) is responsible for generating sentiment reports. This agent takes a unique approach by pre-fetching news, StockTwits, and Reddit data, and directly injecting this structured information into the LLM prompt. This method ensures the LLM has all necessary contextual information from the outset, minimizing the risk of hallucination by avoiding dynamic tool-calling for data retrieval during the LLM's processing. The [`_build_system_message`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L99) function within [`tradingagents/agents/analysts/sentiment_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py) is key to this process, structuring data blocks with XML-like tags to aid the LLM in parsing distinct data types.

Across these analytical agents, common design patterns include the use of factory functions (e.g., [`create_fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L14)) to generate callable agent nodes that process an input [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary and return an updated state. Prompt engineering is extensively used to guide the LLM's behavior and output format, often specifying Markdown tables. The agents also interact with a shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary for context management and to pass generated reports between nodes. Tool-use integration, such as with [`llm.bind_tools`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L53), is a recurring pattern, although the sentiment analyst intentionally deviates from this for specific data sources to ensure data fidelity. For more details on common utilities and design patterns, refer to [Design Patterns and Shared Utilities](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-analysis-agents-design-patterns-and-shared-utilities).

### Fundamentals Analyst Agent

The [`fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L4) agent, defined within [`tradingagents/agents/analysts/fundamentals_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py), is designed to generate comprehensive fundamental analysis reports for specified companies. This agent leverages Large Language Models (LLMs) and integrates with various financial data retrieval tools to gather and interpret key financial information.

The core of the agent's operation involves a [`fundamentals_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L15) that extracts the [`trade_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L49) and [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47) from the system's [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) to establish [`instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L26). It then utilizes a set of specialized tools, including [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), [`get_balance_sheet`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L305), [`get_cashflow`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L337), and [`get_income_statement`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L369), to retrieve relevant financial data. These tools are crucial for providing the LLM with the raw data required for its analysis.

To guide the LLM effectively, a detailed [`system_message`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L25) is constructed. This message instructs the LLM on its role as a fundamental researcher, emphasizing the need for comprehensive analysis, detailed insights, and the presentation of findings in a structured Markdown table. The LLM then processes this information and generates the [`fundamentals_report`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L59), which is incorporated back into the system's [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130). The agent's creation process, through [`create_fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L14), allows for the injection of an LLM instance, enabling flexible integration within a larger multi-agent system. For broader patterns in agent design, refer to [Design Patterns and Shared Utilities](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-analysis-agents-design-patterns-and-shared-utilities).

### Market Analyst Agent

The [`market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L5) agent, defined in [`tradingagents/agents/analysts/market_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py), specializes in analyzing financial markets and generating detailed reports with actionable insights. This agent is designed to be integrated into a larger agentic workflow, such as an agent graph for multi-agent financial trading systems.

At a high level, the [`market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L5) agent operates by:

1. **Contextualizing Analysis**: It establishes the analytical context by retrieving relevant information such as the trade date, asset type, and the company of interest from the overall system state. This context is then used to inform the subsequent data retrieval and analysis steps.
2. **Tool-Use Integration**: The agent is equipped with tools, specifically [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7) and [`get_indicators`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/technical_indicators_tools.py#L6), that allow it to fetch historical stock data and calculate various technical indicators. The agent's underlying large language model (LLM) dynamically invokes these tools as needed during the analysis process.
3. **Dynamic Prompt Generation**: A detailed system message is constructed to guide the LLM. This prompt instructs the LLM on its role as a market analyst, outlining expectations for selecting diverse and complementary technical indicators (e.g., Moving Averages, MACD, RSI, Bollinger Bands, ATR, VWMA), explaining their suitability, and specifying the sequence of tool usage (first retrieving stock data, then calculating indicators). The prompt also dictates the desired output format, emphasizing a nuanced report with actionable insights and a summary table.
4. **Report Generation**: Based on the gathered data and the LLM's analytical capabilities, the agent generates a comprehensive market report. This report synthesizes findings from the technical indicators and provides insights relevant to potential trading decisions.

The design of the [`market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L5) agent prioritizes prompt engineering to ensure the LLM generates high-quality, structured financial analysis. The extensive system message provides explicit instructions, domain-specific knowledge (such as indicator details and usage tips), and clear output formatting requirements. This approach ensures that the agent's analysis is both informed and presented in a consumable format for other agents or users within the trading system.

### Sentiment Analyst Agent

The [`sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L13) agent, primarily implemented in [`tradingagents/agents/analysts/sentiment_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py), is designed to assess market sentiment for a specific stock ticker. Unlike other analyst agents that might rely on LLMs dynamically calling tools to retrieve data, the [`sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L13) employs a strategy of pre-fetching all relevant data—news headlines, StockTwits messages, and Reddit posts—and injecting this information directly into the LLM's prompt. This approach aims to reduce potential LLM hallucination by ensuring the model processes concrete, structured input from the outset, rather than generating content based on tool-calling behavior.

The core logic resides within the [`sentiment_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L46) function, returned by [`create_sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L38). This node orchestrates the data collection for a specified company and trade date. It utilizes functions like [`get_news.func`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L55) for general news, [`fetch_stocktwits_messages`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/stocktwits.py#L30) for retail sentiment, and [`fetch_reddit_posts`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/reddit.py#L59) for community discussions from platforms like r/wallstreetbets. To maintain consistency and prevent disruptions, these data fetching mechanisms are designed to gracefully degrade, returning placeholder strings if actual data is unavailable.

A key aspect of the [`sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L13) 's operation is the [`_build_system_message`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L99) function, which assembles a detailed prompt for the LLM. This system message not only includes the pre-fetched data, clearly delineated by XML-like tags (e.g., [`<start_of_news>`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L116), [`<end_of_news>`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L118)), but also provides extensive guidelines for the LLM on how to interpret various signals. These instructions cover best practices for sentiment analysis, such as understanding StockTwits ratios, Reddit engagement, cross-source divergences, and distinguishing between event-driven news and opinions. This structured input and guidance enable the LLM to generate a comprehensive sentiment report in a single invocation, minimizing reliance on multi-turn interactions or tool-based data retrieval. The agent contributes to the overall trading system by providing a critical sentiment report to other agents in the workflow. For an overview of how agents manage their internal state and schemas, refer to [Agent State Management and Schemas](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-agent-state-management-and-schemas).

Financial analysis agents, such as the [`fundamentals_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L15), [`market_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py#L13), and [`news_analyst_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L12), share several core design patterns and utility functions to ensure modularity, effective state management, and robust LLM interaction.

A common pattern is the creation of agent nodes through factory functions like [`create_fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py#L14) in [`tradingagents/agents/analysts/fundamentals_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/fundamentals_analyst.py) or [`create_market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py#L11) in [`tradingagents/agents/analysts/market_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/market_analyst.py). These functions encapsulate the LLM instance and return a callable node designed to process an input state dictionary and produce an updated one. This approach allows for flexible integration into larger graph-based workflows, as discussed in [Orchestration and Graph-Based Workflows](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-orchestration-and-graph-based-workflows).

All analysis agents rely on consistent state management, reading inputs like [`trade_date`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L49), [`asset_type`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L48), [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47), and [`messages`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/cli/main.py#L45) from a shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary, and writing back LLM responses and generated reports. Utility functions like [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39) are used to contextualize the analysis, providing the LLM with relevant instrument-specific details for improved accuracy.

Prompt engineering is critical across these agents. Detailed [`system_message`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L25) and [`ChatPromptTemplate`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/llm_clients/openai_client.py#L55) configurations guide the LLM's behavior, output format (often including Markdown tables), and analytical focus. The [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) function further customizes the language of the output.

For tools-enabled agents like the [`fundamentals_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L4) and [`market_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L5), tool-use integration is managed by [`llm.bind_tools`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L53). This enables the LLM to dynamically select and execute specialized data retrieval functions (e.g., [`get_fundamentals`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/dataflows/y_finance.py#L248), [`get_stock_data`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/core_stock_tools.py#L7), [`get_indicators`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/technical_indicators_tools.py#L6)) based on the prompt and current context. These tools abstract away the complexities of interacting with various financial data vendors, as described in [Data Retrieval Tools and Utilities](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-data-retrieval-tools-and-utilities).

In contrast, the [`sentiment_analyst`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/CHANGELOG.md?plain=1#L13) (defined in [`tradingagents/agents/analysts/sentiment_analyst.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py)) deviates from this tool-calling pattern. Instead of using [`llm.bind_tools`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/news_analyst.py#L53), it pre-fetches all necessary social media and news data (from sources like StockTwits and Reddit) and injects it directly into the LLM's prompt. This design choice, articulated in [`_build_system_message`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/analysts/sentiment_analyst.py#L99), aims to minimize LLM hallucination by providing concrete, structured input from the outset, ensuring the LLM analyzes existing data rather than attempting to generate it or call tools for its retrieval. This approach demonstrates a flexible strategy for integrating external data, adapting based on the specific analytical task and the reliability concerns of tool usage for certain data types.

## Investment Research and Debate Agents

Investment research and debate agents are responsible for simulating investment discussions, generating arguments for or against a particular investment based on a variety of financial data. These agents are designed to create both pro-investment ("bull") and anti-investment ("bear") arguments by integrating market data, sentiment, news, and fundamentals, while also incorporating the historical context of the debate.

The core of this system lies in two types of agents: the bull analyst and the bear analyst, implemented in [`tradingagents/agents/researchers`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers). The [`create_bull_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L4) and [`create_bear_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L4) functions act as factories to produce these agents, which are essentially nodes in a larger multi-agent system. Each agent, such as the [`bull_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L5) or [`bear_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L5) (within [`tradingagents/agents/researchers/bull_researcher.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py) and [`tradingagents/agents/researchers/bear_researcher.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py) respectively), receives a [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary that contains various research reports (market, sentiment, news, and fundamentals) and the ongoing debate history.

These agents construct detailed prompts for a Large Language Model (LLM). The bull analyst's prompt guides the LLM to focus on aspects like growth potential, competitive advantages, and positive indicators, while also providing a mechanism to counter bearish arguments. Conversely, the bear analyst's prompt directs the LLM to highlight risks, challenges, competitive weaknesses, and negative indicators. After invoking the LLM, the generated argument is formatted and used to update the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) within the shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary, appending the new argument to the debate history. This iterative process allows for a dynamic, turn-based debate where each agent can respond to previous arguments and integrate new information. The system also dynamically adjusts [`target_label`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L16) and [`fundamentals_label`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L17) based on the asset type, ensuring adaptability across different investment instruments. The [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) utility is used to ensure consistent linguistic style and formatting for the LLM's output.

### Bull and Bear Analyst Agents: Argument Generation

The investment debate simulation relies on two distinct research agents: the "Bull Analyst" and the "Bear Analyst." These agents are responsible for generating pro-investment ("bull") or anti-investment ("bear") arguments, respectively, by integrating various data points such as market research, sentiment, news, and fundamentals. The agents also incorporate the historical context of the ongoing debate to refine their arguments.

The [`bull_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L5) function, instantiated via [`create_bull_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L4), acts as the Bull Analyst. It constructs detailed prompts for a Large Language Model (LLM) to generate arguments focusing on growth potential, competitive advantages, and positive indicators. It also includes instructions to counter bearish arguments effectively. The LLM's response is formatted and then used to update the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) within the multi-agent system, contributing to the [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14) of the debate and specifically to [`bull_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L8).

Conversely, the [`bear_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L5) function, created by [`create_bear_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L4), serves as the Bear Analyst. This agent's prompt guides the LLM to identify risks, challenges, competitive weaknesses, and negative indicators. It critically analyzes bullish arguments presented in the [`current_response`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L15) from the opposing agent. Similar to the bull analyst, the bear analyst's generated argument updates the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62), contributing to the overall [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14) and [`bear_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L11).

Both agents dynamically set [`target_label`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L16) and [`fundamentals_label`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L17) based on the [`asset_type`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L48) to tailor their arguments to specific financial instruments like stocks or crypto. The [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) utility is used to ensure consistent linguistic style and format across the generated arguments from both agents. This structured approach allows for a dynamic, turn-based debate where each agent can respond to prior arguments and integrate new research, contributing to a comprehensive analysis of investment opportunities. For more details on the overall orchestration of these agents, refer to [Orchestration and Graph-Based Workflows](https://codewiki.google/github.com/tauricresearch/tradingagents#system-overview-and-interaction-orchestration-and-graph-based-workflows).

### Debate State Management and History

The system manages the progression and context of investment debates through a shared state mechanism. This state, primarily represented by [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) within the agent's overall [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary, tracks the ongoing discussion between "bull" and "bear" research agents. Key components of this state include [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14), which maintains a chronological record of all arguments presented, and [`bear_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L11) and [`bull_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L8), which specifically log the arguments made by their respective analyst types.

When a research agent, such as the bear analyst ([`create_bear_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py#L4) in [`tradingagents/agents/researchers/bear_researcher.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bear_researcher.py)) or the bull analyst ([`create_bull_researcher`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py#L4) in [`tradingagents/agents/researchers/bull_researcher.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/researchers/bull_researcher.py)), generates an argument, it updates the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62). This involves appending the new argument to the general [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14) list and the specific history ([`bear_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L11) or [`bull_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L8)) corresponding to the agent's role. The [`current_response`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L15) field is also updated with the latest argument, and a [`count`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L17) is incremented to track the number of debate turns. This structured approach allows subsequent agents to access and incorporate past arguments, enabling them to formulate informed responses, counter previous claims, and build upon the existing debate context. This process is crucial for simulating a dynamic and iterative investment discussion, influencing the generation of new arguments by both bull and bear researchers. For more on how these agents generate their arguments, refer to [Bull and Bear Analyst Agents: Argument Generation](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-research-and-debate-agents-bull-and-bear-analyst-agents-argument-generation).

## Risk Management and Debate Agents

The risk management debate agents simulate a multi-perspective discussion to thoroughly evaluate a [`trader_investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L67). This system involves three distinct risk analysts: aggressive, conservative, and neutral, each designed to articulate arguments from their specific viewpoint, challenge opposing ideas, and contribute to a shared debate state. This debate mechanism utilizes market data, sentiment reports, news, and fundamental analysis to inform their positions. The agents' definitions and their interaction with state management are found in the [`tradingagents/agents/risk_mgmt`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt) directory.

The [`aggressive_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L15) ([`tradingagents/agents/risk_mgmt/aggressive_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py)) focuses on advocating for high-reward, high-risk investment strategies. It generates arguments that emphasize potential gains while challenging more cautious stances. Conversely, the [`conservative_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L16) ([`tradingagents/agents/risk_mgmt/conservative_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py)) prioritizes asset protection, volatility minimization, and risk mitigation, constructing arguments that promote conservative strategies and counter aggressive proposals. Providing a balanced perspective, the [`neutral_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L17) ([`tradingagents/agents/risk_mgmt/neutral_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/neutral_debator.py)) critiques both aggressive and conservative viewpoints, advocating for a moderate risk approach to ensure a comprehensive risk assessment within the debate.

Each debater agent is implemented as a factory function that returns a node configured with a Large Language Model (LLM). These nodes extract relevant financial reports and the current debate status from a shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary, formulate prompts for the LLM based on their role, and then update the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) within the [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) with their generated arguments. The [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) tracks the debate's [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14), individual debater responses, the [`latest_speaker`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L32), and the turn [`count`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L17), facilitating a dynamic and iterative flow where each agent's contribution influences subsequent turns. The process of managing this multi-agent debate state is further detailed in [Multi-Agent Debate State Management](https://codewiki.google/github.com/tauricresearch/tradingagents#risk-management-and-debate-agents-multi-agent-debate-state-management). The output of these debates informs the [Portfolio Manager: Deriving Final Trade Decisions](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-portfolio-manager-deriving-final-trade-decisions).

### Aggressive Risk Debater Agent

The [`aggressive_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L15) agent plays a role in the system's risk management debate by advocating for high-reward, high-risk investment strategies. This agent is designed to challenge conservative and neutral viewpoints within a multi-agent debate, aiming to persuade towards more opportunistic investment decisions.

The agent's functionality is initiated by a factory function, [`create_aggressive_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py#L4) in [`tradingagents/agents/risk_mgmt/aggressive_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py), which configures an agent node with a large language model (LLM). The [`aggressive_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py#L5) function then operates by extracting relevant financial reports—such as market, sentiment, news, and fundamentals—along with the current investment plan and the ongoing debate state from a shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary.

It constructs a prompt for the LLM that instructs it to act as an "Aggressive Risk Analyst." This prompt emphasizes the potential for high returns, encourages challenging opposing arguments, and requires the incorporation of provided market and sentiment data to support its stance. Specifically, it responds to the arguments previously made by conservative and neutral analysts. After the LLM generates its argument, the [`aggressive_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py#L5) updates the shared [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70). This update includes appending the aggressive analyst's argument to the overall debate history and its specific history, identifying "Aggressive" as the latest speaker, and recording its current response. This iterative update mechanism allows the debate to progress dynamically, with each agent's contribution influencing subsequent turns. The process of managing the debate's state is consistent across all debater agents, as detailed in [Multi-Agent Debate State Management](https://codewiki.google/github.com/tauricresearch/tradingagents#risk-management-and-debate-agents-multi-agent-debate-state-management).

### Conservative Risk Debater Agent

The [`conservative_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/__init__.py#L16) agent, created by the [`create_conservative_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L4) factory function in [`tradingagents/agents/risk_mgmt/conservative_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py), plays a role in promoting asset protection and risk mitigation within the multi-agent risk debate system. Its function is to construct arguments that advocate for conservative investment strategies, highlighting potential risks and emphasizing the importance of volatility minimization.

During a debate, the [`conservative_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L5) processes a shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) dictionary that contains various financial reports such as [`market_report`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L54), [`sentiment_report`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L55), [`news_report`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L56), and [`fundamentals_report`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L59), along with the [`trader_investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L67) being debated. It also accesses the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) to understand the current arguments put forth by other debaters, specifically the aggressive and neutral analysts.

Based on this information, the [`conservative_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L5) formulates a prompt for a Large Language Model (LLM). This prompt guides the LLM to generate a response from the perspective of a "Conservative Risk Analyst," focusing on counter-arguments to higher-risk proposals and reinforcing the principles of prudent asset management. After the LLM generates its argument, the [`conservative_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L5) updates the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) by appending its response to the debate [`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14) and its specific [`conservative_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L25), marking itself as the [`latest_speaker`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L32), and incrementing the [`count`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L17) of debate turns. This iterative process ensures that the conservative viewpoint is continuously integrated into the ongoing risk assessment. For details on how the debate state is managed, refer to [Multi-Agent Debate State Management](https://codewiki.google/github.com/tauricresearch/tradingagents#risk-management-and-debate-agents-multi-agent-debate-state-management).

This iterative process facilitates a dynamic debate where each agent's contribution influences subsequent turns.

### Multi-Agent Debate State Management

The multi-agent financial trading system orchestrates debates between various risk analysts by maintaining a shared state that captures the dynamic progression of their arguments. This state, primarily managed within the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) sub-dictionary of a broader [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130) object, acts as the central repository for contextual information. Each debater agent—aggressive, conservative, and neutral—accesses and updates this shared state as it formulates and presents its arguments.

The [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) tracks critical elements of the debate:

- **[`history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L14)**: This component records the chronological flow of arguments, ensuring that each agent can refer to previous turns and counter points made by other participants.
- **Individual Debater Responses**: Specific fields such as [`aggressive_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L22), [`conservative_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L25), and [`neutral_history`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L28) (or [`current_aggressive_response`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L33), [`current_conservative_response`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L36), [`current_neutral_response`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L39)) store the sequence of arguments presented by each debater, allowing for an isolated view of their contributions.
- **[`latest_speaker`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L32)**: This identifies the agent that last contributed to the debate, facilitating turn-taking logic and enabling subsequent agents to direct their responses appropriately.
- **[`count`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L17)**: This metric tracks the number of turns in the debate, providing a mechanism to monitor its progress or to implement stopping conditions.

Each debater agent, such as the [`aggressive_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py#L5) created by [`create_aggressive_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py#L4) in [`tradingagents/agents/risk_mgmt/aggressive_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/aggressive_debator.py), or the [`conservative_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L5) from [`create_conservative_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py#L4) in [`tradingagents/agents/risk_mgmt/conservative_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/conservative_debator.py), and the [`neutral_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/neutral_debator.py#L5) from [`create_neutral_debator`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/neutral_debator.py#L4) in [`tradingagents/agents/risk_mgmt/neutral_debator.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/risk_mgmt/neutral_debator.py), extracts relevant reports (e.g., market, sentiment, news, fundamentals) and the proposed [`trader_investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L67) from the shared [`state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/LICENSE#L130). They then construct prompts for a Large Language Model (LLM) to generate their arguments, often addressing points raised by other debaters. After the LLM produces a response, the agent updates the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) with its new argument, the identity of the [`latest_speaker`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L32), and increments the [`count`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L17). This iterative process, where each agent's contribution modifies the shared state, drives the multi-agent debate forward, leading to a comprehensive risk assessment. This dynamic interaction is central to the system's ability to simulate a thorough review of investment plans. The final outcome of this debate is then utilized by investment management agents to synthesize decisions, as detailed in [Investment Management and Decision Agents](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents).

## Investment Management and Decision Agents

The investment management and decision agents are responsible for generating and synthesizing investment and trading decisions within the multi-agent system. These agents translate the outcomes of various debates and analyses into structured plans and concrete trade proposals.

The process begins with the [`create_research_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L16) agent, which synthesizes the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) to produce a structured [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61). This involves processing the history of pro- and anti-investment arguments generated by the [Investment Research and Debate Agents](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-research-and-debate-agents). The [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19) function, located in [`tradingagents/agents/managers/research_manager.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py), constructs an LLM prompt that includes instrument context, a rating scale, and the debate history. It then utilizes the LLM to generate the [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61), ensuring adherence to a predefined schema while also providing a fallback to free-text generation if structured output is not feasible.

Following the creation of the [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61), the [`create_portfolio_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L24) agent takes over. This agent is responsible for deriving the final trade decisions by synthesizing the output of the risk analyst debates ([`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70)) and the investment plan. The [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27) function, found in [`tradingagents/agents/managers/portfolio_manager.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py), aggregates diverse information such as the company of interest, the full history of risk debates (from [Risk Management and Debate Agents](https://codewiki.google/github.com/tauricresearch/tradingagents#risk-management-and-debate-agents)), the [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61), and any past lessons or context. It constructs a comprehensive prompt for the LLM to generate a [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171), which also adheres to a structured output schema with a free-text fallback. This ensures that the final decision is well-informed by all preceding analyses and debates, including those from the [Financial Analysis Agents](https://codewiki.google/github.com/tauricresearch/tradingagents#financial-analysis-agents).

Both the [`create_research_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L16) and [`create_portfolio_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L24) agents leverage robust mechanisms for interacting with Large Language Models, particularly the [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) function for enforcing schema-based output and [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) for graceful fallback to free-text generation, as detailed in [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms). This ensures that the generated investment plans and trade decisions are both machine-readable and resilient to LLM output variations. Additionally, these managers utilize utility functions like [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39) and [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) to enrich LLM prompts with relevant instrument-specific details, enhancing the quality and accuracy of the generated outputs.

### Research Manager: Synthesizing Investment Plans

The [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19) within the trading agent system is responsible for consolidating the diverse arguments generated during an investment debate into a coherent and structured [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61). This manager acts as a facilitator, taking the full [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) —which includes the historical exchange of pro-investment ("bull") and anti-investment ("bear") arguments—and synthesizing it into a concrete investment recommendation.

The core process involves leveraging Large Language Models (LLMs) to perform this synthesis. The manager constructs a detailed prompt for the LLM that incorporates critical context such as the [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47), a defined [`Rating Scale`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L31) (e.g., Buy, Hold, Sell), and the complete [`Debate History`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L42). This allows the LLM to understand the nuances of the discussion and formulate an informed recommendation.

To ensure the LLM's output is predictable and machine-readable, the system employs mechanisms for structured output. Specifically, the [`create_research_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L16) function configures the LLM using [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) (from [`tradingagents/agents/utils`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils)) to adhere to the [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) schema. This forces the LLM to generate its recommendation in a predefined format, making it easier for subsequent agents or processes to consume and act upon. In cases where structured output might fail or not be desired, a robust [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) function provides a graceful fallback to free-text generation, ensuring that an output is always produced.

The resulting [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) is then stored back into the [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62), marking a pivotal step where qualitative debate is transformed into a quantitative and actionable investment strategy. This structured plan can then be utilized by other agents in the system, such as the [Portfolio Manager: Deriving Final Trade Decisions](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-portfolio-manager-deriving-final-trade-decisions), to make final trade decisions. For further details on how various agents utilize and manage state, refer to [Agent State Management and Schemas](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-agent-state-management-and-schemas).

### Portfolio Manager: Deriving Final Trade Decisions

The [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27) is responsible for synthesizing the outcomes of risk analyst debates and existing investment plans into a concrete [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171). This node, generated by the [`create_portfolio_manager`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L24) function in [`tradingagents/agents/managers/portfolio_manager.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py), functions as a Portfolio Manager within the multi-agent system.

The core logic of the [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27) involves extracting various contextual elements from the system's shared state. These include the [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47), the [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) (which contains the history of the risk management debate), the previously formulated [`investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L65) [Research Manager: Synthesizing Investment Plans](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-research-manager-synthesizing-investment-plans), a [`trader_investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L67), and any relevant [`past_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L74).

A detailed prompt is constructed for a Large Language Model (LLM), incorporating this aggregated information. This prompt includes specific instrument context derived using [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39), definitions for a [`Rating Scale`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L31) (e.g., Buy, Overweight, Hold, Underweight, Sell), the details from both the research and trader investment plans, lessons from past decisions, and the complete history of the risk analysts' debate. The [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) utility adds language-specific guidance to ensure the LLM generates an appropriate response.

A key aspect of this process is the utilization of structured output from the LLM, coupled with a fallback mechanism. The system attempts to obtain a structured [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) object by configuring the LLM using [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) to adhere to a predefined schema. If the LLM successfully generates a structured output, it is directly used. In cases where structured output is not feasible or fails, [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) provides a graceful fallback to free-text generation. The resulting decision, whether structured or free-text, is then rendered into a human-readable markdown string using [`render_pm_decision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L209), ensuring consistency in presentation. This final decision, along with the updated [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70), is then incorporated back into the system's state. For more details on the structured output and fallback mechanisms, refer to [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms).

### Structured Output and Fallback Mechanisms for Decision Agents

The [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19) and [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27) agents both employ a shared design pattern to ensure that the Large Language Models (LLMs) they interact with produce structured output, while also providing a robust fallback to free-text generation. This dual approach addresses scenarios where structured output might not be feasible or desired.

Central to this pattern is the [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) mechanism, which configures the LLM to adhere to a predefined schema, such as [`ResearchPlan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L61) for the [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19) or [`PortfolioDecision`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L171) for the [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27). This ensures that the generated investment plans and portfolio decisions conform to a consistent, machine-readable format.

Complementing [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) is the [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) function. This utility attempts to obtain a structured response from the LLM, but if that fails, it gracefully falls back to generating free-text. This ensures that the system can always produce a response, even if it cannot strictly conform to the expected schema. After a decision is rendered, either from a structured object or free-text, it is stored in the agent's state, such as [`investment_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L62) for the [`research_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/research_manager.py#L19) or [`risk_debate_state`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L70) for the [`portfolio_manager_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/managers/portfolio_manager.py#L27), for further processing or logging. This approach guarantees both the predictability of structured data when possible and the resilience of a free-text option.

## Trading Execution Agents

The system translates strategic investment plans into concrete transaction proposals through a dedicated trading agent. This agent's primary function is to interpret an [`investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L65) generated by other components of the system, and convert it into a structured [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) suitable for execution. The agent leverages large language models (LLMs) to perform this transformation.

The core logic resides within the [`trader_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L23) function in [`tradingagents/agents/trader/trader.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py). This function extracts pertinent information such as the [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47), [`asset_type`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L48), and the [`investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L65) from the current system state. It then enriches the LLM's prompt with an [`instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L26), which provides specific details about the asset being considered. This context, along with a system message that defines the agent's role as a trading agent, guides the LLM in generating its recommendation.

A key aspect of this process is ensuring that the LLM's output adheres to a predefined structure, specifically the [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) schema. This is achieved through mechanisms that bind the LLM to this schema, ensuring that the generated proposal includes necessary fields for a transaction. In cases where structured output might not be directly achievable by the LLM, a fallback mechanism allows for free-text generation, maintaining the system's robustness. This approach for handling structured output and fallbacks is a common pattern across decision-making agents, as further discussed in [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms) and [Structured Output and Fallback Mechanisms for Decision Agents](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-structured-output-and-fallback-mechanisms-for-decision-agents). The [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) includes specific recommendations (buy, sell, or hold) and grounds its reasoning in the analysis reports and the initial investment plan. Further details on how the LLM's prompts are constructed and how structured output is enforced can be found in [Instrument Context Building for Prompt Engineering](https://codewiki.google/github.com/tauricresearch/tradingagents#trading-execution-agents-instrument-context-building-for-prompt-engineering) and [Structured Output Enforcement and Fallback Mechanism](https://codewiki.google/github.com/tauricresearch/tradingagents#trading-execution-agents-structured-output-enforcement-and-fallback-mechanism).

The [`trader_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L23) function, defined in [`tradingagents/agents/trader/trader.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py), serves as the core logic for the Trader Agent, transforming investment plans into concrete transaction proposals. This function is responsible for preparing the necessary context, constructing a detailed prompt, and invoking a Large Language Model (LLM) to generate [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) objects.

When the [`trader_node`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L23) is executed, it first extracts key pieces of information from the current system state: the [`company_of_interest`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L47), the [`asset_type`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L48), and the [`investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L65) that has been developed by the Research Manager. To enrich the LLM's understanding and guide its decision-making, it then constructs an [`instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L26) using relevant details about the financial instrument in question. This context, along with specific language instructions, is crucial for building a comprehensive prompt.

The prompt sent to the LLM includes a system message that clearly defines the Trader Agent's role: to analyze market data, provide specific buy, sell, or hold recommendations, and ensure that its reasoning is anchored in existing reports and the provided research plan. A user prompt then presents the [`investment_plan`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_states.py#L65) for the [`company_name`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/graph/propagation.py#L20), incorporating the previously generated [`instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/trader/trader.py#L26). This structured prompting approach aims to elicit a well-reasoned trading proposal.

The LLM is invoked to generate a [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109), which is a structured output detailing the recommended transaction. The system utilizes mechanisms to encourage structured output from the LLM, but also includes a fallback to free-text generation in cases where structured output cannot be reliably produced. The result of this process includes the LLM's response as an [`AIMessage`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/cli/main.py#L951) within the system's message history, the generated [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) (or its free-text equivalent), and the name of the sender, [`Trader`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/README.md?plain=1#L87). ### Structured Output Enforcement and Fallback Mechanism

The system employs a robust mechanism to ensure that Large Language Models (LLMs) produce structured outputs when generating trading proposals, while also incorporating a fallback to free-text generation for resilience. This is achieved through the use of two core utility functions, [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) and [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48), located in [`tradingagents/agents/utils/structured.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py).

The [`bind_structured`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L31) function attempts to configure an LLM to generate output conforming to a specified Pydantic schema, such as the [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) schema used by the Trader agent. This helps in enforcing a consistent and parseable format for critical trading decisions. If the LLM provider does not natively support structured output for a given model, or if any errors occur during this binding process, the function logs a warning and gracefully indicates that structured output is not available for that particular LLM.

Subsequently, the [`invoke_structured_or_freetext`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/structured.py#L48) function is responsible for invoking the LLM. It prioritizes the use of the structured-bound LLM if one was successfully configured. If the structured invocation is successful, the output is processed and rendered into a string format, typically Markdown, for further use. However, if the structured invocation fails—due to issues like malformed JSON from the LLM or transient API errors—or if structured output was not supported in the first place, the system automatically falls back to invoking the original LLM to generate a free-text response. This fallback mechanism ensures that the agent pipeline continues to function without interruption, even if the preferred structured output cannot be obtained, and logs a warning for diagnostic purposes. This pattern is also used by other decision agents such as the [Research Manager: Synthesizing Investment Plans](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-research-manager-synthesizing-investment-plans) and the [Portfolio Manager: Deriving Final Trade Decisions](https://codewiki.google/github.com/tauricresearch/tradingagents#investment-management-and-decision-agents-portfolio-manager-deriving-final-trade-decisions).

### Instrument Context Building for Prompt Engineering

The trading system enriches Large Language Model (LLM) prompts with instrument-specific details and language instructions to enhance the quality and accuracy of generated outputs, particularly for [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) objects. This process involves two key functions: [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39) and [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23), both located in [`tradingagents/agents/utils/agent_utils.py`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py).

The [`build_instrument_context`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L39) function generates a descriptive string for a given financial instrument, such as a stock ticker or crypto asset. This string provides explicit guidance to the agents, ensuring correct interpretation of the instrument's type and format. For example, it differentiates between "asset" and "instrument" labels and includes specific hints for crypto assets, helping the LLM understand how to correctly process exchange-qualified tickers.

Complementing this, the [`get_language_instruction`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/utils/agent_utils.py#L23) function dynamically creates a language instruction string based on the system's configured output language. If the output language is set to English, it returns an empty string to avoid unnecessary tokens. Otherwise, it generates a directive like "Write your entire response in {language}." This ensures that all agent outputs, including [`TraderProposal`](https://github.com/tauricresearch/tradingagents/blob/61522e103e61601c553b4544abcd53fa7ebf9f1d/tradingagents/agents/schemas.py#L109) documents, are consistently localized, improving the clarity and usability of the generated content. This process contributes to the overall structured output generation discussed in [Structured Output with LLMs and Fallback Mechanisms](https://codewiki.google/github.com/tauricresearch/tradingagents#agent-definitions-and-roles-structured-output-with-llms-and-fallback-mechanisms).
